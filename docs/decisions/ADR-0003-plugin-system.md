# ADR-0003: Adopt issue-driven development before feature work

## Status

Accepted — 2026-07-20

## Context

An open-source project needs a durable explanation for why a change exists,
even when it is initially maintained by one person.

## Decision

Material work starts with a GitHub issue and follows the sequence: issue,
discussion, branch, commit, pull request, and merge. GitHub Projects is the
planning view for Backlog, Sprint, Doing, Review, and Done.

## Consequences

There is a small planning cost before implementation, but decisions, scope,
and release history remain easier to understand and audit later.
